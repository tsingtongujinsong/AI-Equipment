# 组织建设

## 组织设计原则

1. 小而精：关键岗位优先、避免冗余层级
2. 专业化：行业、产品、交付职责清晰
3. 可协同：跨团队协作链路短、决策路径清晰
4. 可扩展：支持从启动期到成长期平滑扩展

## 组织形态

按“行业线 + 产品线 + 交付中心”重构组织。

- 行业线：负责行业洞察、客户经营、方案落地
- 产品线：负责平台能力、模块规划、版本迭代
- 交付中心：负责项目实施、质量保障、售后服务

## 职责边界

### 行业线

- 行业研究与机会识别
- 客户需求澄清与业务价值定义
- 标杆客户经营与复购推动

### 产品线

- 产品路线图与模块管理
- 技术标准与接口规范
- 跨项目复用策略与版本治理

### 交付中心

- 项目计划、资源协调、现场交付
- 质量门禁与验收管理
- 运维响应与持续优化

## 决策机制

| 决策类型 | 责任角色 | 参与角色 | 节奏 |
|---|---|---|---|
| 战略方向 | 部门负责人 | 核心管理团队 | 季度 |
| 产品路线图 | 产品负责人 | 技术+行业线 | 月度 |
| 重大项目立项 | 交付负责人 | 商务+技术+财务 | 按需 |
| 关键岗位录用 | 部门负责人 | 面试委员会 | 按需 |

## 会议节奏

- 每日站会：执行层问题同步
- 每周项目例会：里程碑、风险、资源协调
- 双周产品评审：需求优先级与版本决策
- 月度经营复盘：收入、毛利、回款与客户成功
- 季度组织复盘：组织效率与能力短板改进

## 组织成熟度目标

- 启动期：职责清晰、流程可执行
- 成长期：跨团队协同高效、复用机制稳定
- 稳定期：组织可复制、人才梯队与机制自驱
